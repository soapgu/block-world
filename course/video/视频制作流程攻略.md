# 拳击编程课视频制作流程攻略

这份攻略记录当前工程的制作与复现路径：用 Remotion 制作棋盘和字幕动画，用 Edge TTS 生成教学旁白，再用 FFmpeg 将教学主课与独立歌曲视频拼接。最终交付为 `out/boxing-lesson.mp4`、`out/教学版.srt`，独立歌曲交付为 `out/boxing-rap.mp4`、`out/说唱版.srt`。这些媒体文件保存在本地 `out/`，不纳入 Git。

## 1. 先锁定教学内容

对照[原理讲义](../编程课-拳击原理.md)、[练习题](../编程课-拳击练习题.md)和[讲义勘误](讲义勘误.md)检查旁白、画面与答案：

- 身体占 `(5,3)、(6,3)、(5,4)、(6,4)` 四格。
- 拳臂从起点向下**再伸三格**，连起点共四格；与身体至少重叠一格才算打中。
- 五题答案依次为：打中、打空、打空、打中、打空。
- `5 ≤ x ≤ 6` 且 `5 ≤ y ≤ 7` 只适用于本课身体固定、拳头从上方向下出拳的场景。其他场景应逐格判断重叠。

场景旁白和题目数据在 `src/content.json`；教学分镜见[脚本与分镜](脚本与分镜.md)。先改内容，再生成配音和时间轴，避免修改画面文字后沿用旧字幕。

## 2. 准备本机环境与素材

需要 macOS、Google Chrome、Node.js、Python 3 和 FFmpeg；`ffprobe` 随 FFmpeg 提供。Edge TTS 使用在线语音服务，首次生成或更改旁白时需要网络。进入工程目录后安装依赖：

```bash
cd course/video
npm install
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-audio.txt
```

棋盘与题目配图位于 `public/diagrams/`。游戏开场从现有拳击原型录制；需要重新取得开场素材时运行：

```bash
node tools/capture_game.mjs
```

脚本将游戏片段写入 `public/video/gameplay.mp4`。教学版前 35 秒使用游戏开场；其余讲解以棋盘动画为主。`public/video/`、`public/audio/`、`.venv/` 和 `out/` 都是本地素材或产物目录，已被 Git 忽略。

## 3. 准备独立歌曲

先核对[新版歌曲歌词](新版歌曲歌词.md)、[歌曲生成记录](歌曲生成记录.md)和[歌曲视频制作记录](歌曲视频制作记录.md)。歌曲音源可从选定的音乐平台导出；本工程当前使用 `out/boxing-song-final.mp3`。歌词与画面共用 `src/song-timeline.json`，独立画面由 `src/song.tsx` 的 Remotion `Song` composition 渲染。

只有在歌曲音源或逐句时点变更、需要重新制作独立歌曲视频时，才执行以下步骤：

```bash
mkdir -p public/audio out
cp out/boxing-song-final.mp3 public/audio/boxing-song-final.mp3
node tools/export_song_srt.mjs
npm run render:rap -- --browser-executable='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'
```

渲染前应试听音源并在 `src/song-timeline.json` 逐句校对实际唱词与起止时间，随后生成 `out/说唱版.srt`；画面字幕和 SRT 才能保持一致。**当前版本只有第一句从 11.5 秒开始这一时间锚点经过用户确认，其余逐句时间为近似分配，仍需人工试听校正。**不能把现有歌曲字幕当作已经完成精确对时的版本。校正后重新导出歌曲视频与 SRT，再制作教学版。

若沿用已有歌曲，只需确认 `out/boxing-rap.mp4` 和 `out/说唱版.srt` 存在并匹配；无需重渲染歌曲。参考录音仅用于分析风格，不进入成片；歌曲应使用原创歌词和旋律。

## 4. 生成教学旁白、音乐、动画与字幕

确认歌曲视频及其 SRT 已备齐后运行：

```bash
npm run render:lesson
```

入口 `tools/render_lesson.py` 先调用 `tools/build_lesson_audio.py`。后者用 `zh-CN-YunjianNeural`、语速 `+10%` 为各段旁白生成音频，读取 Edge TTS 返回的字词边界，按**实际语音长度**排场景和字幕；同时生成轻快电子背景音乐、音效、`src/lesson-timeline.json`、`src/lesson-captions.json` 及教学主课 SRT。重复构建时，可复用未变更旁白的本地缓存。

Remotion 的 `LessonMain` composition 依据同一时间轴绘制棋盘、坐标、拳臂、倒计时和字幕，以 1920×1080、30 fps 渲染教学主课。五题各先完整倒数 3 秒，倒数结束后才逐格出拳、播放提示音、显示命中颜色与答案；答案旁白紧接揭晓。背景音乐在旁白下自动压低，进入歌曲前淡出。不要运行旧的 `tools/build_audio.py`，它对应旧版说唱流程。

`tools/render_lesson.py` 随后用 FFmpeg 拼接当次的 `out/boxing-rap.mp4`，将歌曲 SRT 按主课实际时长后移，输出 `out/boxing-lesson.mp4` 和 `out/教学版.srt`。构建前后会核对歌曲视频 SHA-256；`out/lesson-render-manifest.json` 记录时长、字幕数量及校验值。重新导出分镜文档可运行 `python3 tools/export_docs.py`。

## 5. 完整验收

1. **画面与知识点**：开场约 35 秒；身体四格、拳臂四格及固定场景限定正确；五题依次打中、打空、打空、打中、打空。逐题检查倒数最后一帧没有提前揭晓，倒数结束后动画与结果顺序正确。
2. **声音**：完整试听旁白与歌曲，重点听坐标、数字、女声实际唱词、音效和背景音乐音量；确认没有截字、长时间固定空白或背景音乐盖过讲解。音量测量不能代替试听。
3. **字幕**：逐句检查教学旁白字幕与语音边界、歌曲字幕与实际演唱是否同步。歌曲当前尚有未完成的逐句对时工作，必须单独校正。
4. **技术检查**：用 `ffprobe` 核对 1920×1080、30 fps、音轨和时长；用 `ffmpeg -v error -i out/boxing-lesson.mp4 -f null -` 检查全片可解码；核对主课与歌曲片段时长之和，并用 `shasum -a 256 out/boxing-rap.mp4` 对照清单中的歌曲校验值。

本次实际构建与检查结果见[教学版重制记录](教学版重制记录.md)。重新生成后的时长与校验值以新产物为准，不要把记录中的数值当成固定目标。
